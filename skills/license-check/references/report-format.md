# 报告要求

先给结论及其适用范围，再呈现发现和建议。报告至少包括：

- 受检工程、工程许可证和已确认的使用／分发方式。
- 检查范围：生态、锁文件／环境、实际包数量、未覆盖内容。Python 明确注明已安装环境未与锁文件验证一致；本地多余 npm 包不直接认定为发布依赖。
- 发现：已确认冲突、义务遗漏、需要确认、在已检查范围内未发现问题。无需填充空类别。
- 每项发现包含组件及版本、证据路径（必要时摘录）、条件、判断理由和最小建议动作。具体条款结论附官方来源。
- 完整性：所有 issues 的处理结果；同类项可合并，但列出涉及包／路径。解释执行失败或无法收集的内容。

脚本 JSON schema_version 为 1。status=collected 仅指取证完成；incomplete 表示有缺失或范围问题。scopes 说明取证模式，packages 保留包级声明、依赖声明及许可原文，project_license_files 保留工程目录中的相关文件（包括 vendor 等候选文本，不能全部当作工程自身授权），excluded_project_directories 列明跳过的目录名，issues 包含 code/path/message。JSON 没有扫描时间，便于同一输入得到一致结果。

退出码：0 取证完成；1 证据不完整；2 参数或目标路径错误。脚本的意外运行错误也应作为执行失败处理，不能当作无问题。
